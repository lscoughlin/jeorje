# Testing

## Rules

- `mvn verify` passes offline. No test needs a network, a real LLM, or real embedding model files.
- Each behavior change has a test in `src/test/java` of the module that owns the behavior.
- Tests use the JUnit Jupiter API (the JUnit 5 API). The parent pom imports it through the JUnit 6.x BOM.
- Tests use a temporary directory for each test. No test writes to the real `${HOME}/.jeorje` or to a real project `.jeorje`.

## Stubs

Each port in [architecture.md](architecture.md) has a stub in a shared test-support module (`jeorje-testkit`). `jeorje-testkit` depends on `jeorje-core`, so the tests of `jeorje-core` cannot use it. The core tests have their own doubles in test support classes, for example `AgentTestSupport` and `CompactionTestSupport`. The other modules use `jeorje-testkit` in test scope.

| Port | Stub | Behavior |
|------|------|----------|
| `LlmClient` | `ScriptedLlmClient` | Plays a fixed list of responses, including streamed tokens and tool calls. It records each request. |
| `Embedder` | `StubEmbedder` | Makes deterministic vectors from a hash of the text. |
| `Transport` | `InMemoryTransport` | Connects many peers in one JVM. Its `InMemoryNetwork` can drop, delay, or reorder messages and can cut links to make a partition. |
| `Tool` | `FakeTool` | Returns a set result, or throws, or blocks until cancelled. |
| `PermissionPolicy` | `FixedPolicy` | Returns a set decision. |
| `Clock` | `ManualClock` | Time moves only when the test moves it. |

`jeorje-testkit` also has two helpers: `TempWorkspace` makes a temporary workspace, and `InMemoryContextStore` is an in-memory store for context tests. The stub `InMemoryTransport` and its helper `InMemoryNetwork` are in the package `testkit.swarm`.

## Live tests

Four tests run only when `JEORJE_LIVE=1` is set: `LiveSmokeTest` and `LivePlanImplementTest` (`jeorje-cli`), `OpenAiCompatibleClientLiveTest` (`jeorje-llm`), and `OnnxEmbedderLiveTest` (`jeorje-index`). `mvn verify` skips them.

## Test levels

### Unit tests

- Message model and Jackson round trips.
- `TurnChunker` boundaries, overlap, and large tool results.
- Compaction triggers, eviction order, and pinned items.
- Protection classes: `PROTECTED` chunks never change, a resolved error becomes `AGGRESSIVE`, immediate file paths survive at every level, and `CAREFUL` chunks stop at level 2.
- Decision notes: the note has structured bullets, every keyword and path is in the original chunk, and the note is shorter than the original.
- Token-level pruning: the pruned text is always an ordered subsequence of the original text, and the kept share is inside the level target.
- Rejection of invalid compactor answers (overlapping spans, a wrong ratio, a keyword that is not in the chunk), and the fallback pruner.
- Keyword hints: each keyword is in the original text, and the hint as a TEXT query finds the pruned chunk in the top 3 results.
- Prompts: `text` and `file` both set is an error, `append` and `replace` build the right prompt, the project value overrides the user value, unknown variables are rejected, an edited prompt file takes effect on the next request, and the fixed parts and the output contract stay in a custom prompt.
- Model roles: `/model`, `/compactor`, and `/advisor` change the right client. `/advisor off` removes the `advisor` tool.
- Permission rule matching and the strictest-decision rule.
- `--yes` and `--yolo`: `--yes` keeps `DENY` rules and the sandbox, `--yolo` allows every action, `--yolo` wins over `--yes`, secrets never reach logs or child processes in `--yolo`, and the audit log records the source `yolo`.
- Path sandbox: symbolic links, `..` segments, and paths outside the workspace.
- Each built-in tool, with the file-state check for `write` and `edit`.
- `read` front matter: a marker on line 1, a marker after a license header or shebang, a marker with each comment prefix (`//`, `#`, `*`, `--`, `;`, `%`, `<!--`, `/*`), a marker on line 26 is ignored, a Markdown heading underline, horizontal rules, and a multi-document YAML file produce no front matter and no note, `.yaml` and `.json` files are not checked, a block with no closing marker is ignored, a block of more than 40 lines is ignored, and a read with an `offset` does not check front matter.
- `read` directory context: `AGENTS.md` (not in the root), `README.md`, `llms.txt`, and `llm.txt` in the file directory and in each parent up to the workspace root, no file above the workspace root, root-to-leaf order, the 2,000-character cut, the 20-line fallback, one delivery for each directory for each agent state, and no output when the files are missing.
- OpenAI wire mapping: `Text`, `ToolUse`, and `ToolResult` to the chat format and back, with recorded streaming fragments.

### Index tests

- A real Lucene index in a temporary directory with `StubEmbedder`.
- TEXT, RAW, VECTOR, and HYBRID results, and the fallback of HYBRID to TEXT.
- Filters apply before ranking: a strong match outside the filter does not hide a weaker match inside it.
- Schema version upgrade and embedding drift errors.
- Text-only mode when the embedder is missing.

### Agent loop tests

- `ScriptedLlmClient` and `FakeTool` run complete turns.
- Parallel and sequential tool runs.
- Retry with backoff on HTTP 429 and 5xx, with a recording sleeper in place of real waits (`AgentSettings.Sleeper`).
- Cancellation leaves a valid history, with `interrupted` results for open tool calls.
- The step limit stops a looping model.

### Swarm tests

- `InMemoryTransport` runs 3 to 20 peers in one JVM.
- Join with a WKA list, and join by gossip only.
- Failure detection: `ALIVE` to `SUSPECT` to `DEAD`, and refutation by a higher incarnation.
- Partition and heal.
- Delegation to a remote subagent, steering, and cancellation.
- The handshake rejects a wrong token.

### End-to-end tests

- `jeorje run` with `ScriptedLlmClient` in a temporary workspace. The test checks the files, the transcript, and the index.
- A live smoke test with a real OpenRouter key is outside `mvn verify`. It runs only when `JEORJE_LIVE=1` is set. It reads the key from the environment variable `OPENROUTER_API_KEY` and uses the default model `~deepseek/deepseek-flash-latest`. The test checks a streamed answer, a tool call, and the usage values. It never prints the key. Offline tests never need a key.

## Determinism

- Tests wait for a result with latches, `ManualClock`, or the events of the system under test. A test that must poll uses a loop with a deadline. A few tests use a short `Thread.sleep` inside such a loop.
- Tests give the random source a fixed seed.
- Tests that use virtual threads wait for the events they need and have a timeout of 10 s.

## Continuous integration

The repository has no CI configuration file. The build needs JDK 25 (`maven.compiler.release` is 25). The command `mvn verify` runs all tests. After a first online build, `mvn -o verify` runs offline on a warm cache. When the JDK is version 21 or newer, the Maven profile `jdk-vector` adds `--add-modules jdk.incubator.vector` to the test JVM, so that Lucene can use its SIMD path.
